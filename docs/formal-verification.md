# Formal verification: what is proven, and what is trusted

This document states — precisely and conservatively — what the Lean 4 proofs in
`lean/Sound.lean` (the UNSAT direction: the LRAT certificate checker),
`lean/SatWitness.lean` (the SAT direction: the witness checker, TR-044) and
`lean/QueryCheck.lean` (the query direction: the certificate-carried term DAG
re-check, #192 phase 4 / TR-062) do and do not establish about ordeal's
trusted checker crate. It is written to be
checkable line by line, not to impress. If a claim here cannot be backed by
the source or a tool run, it does not belong here.

## The one-sentence claim

> The **LRAT/RUP checking algorithm** `kernel::check_steps` is machine-checked
> in Lean 4 to be **sound**: if it accepts a certificate's steps against a CNF,
> that CNF is unsatisfiable — proved with **zero `sorry`**, over the
> **Aeneas-generated model** of the Rust source.

Since #192 phase 4 there is a second sentence, about the query rather than
the CNF:

> The **query re-check** `kernel::check_query` is machine-checked to be
> **sound**: if it accepts an LRAT certificate against a term DAG, no
> assignment to the DAG's variables makes every asserted root true — with
> no side conditions (the DAG's well-formedness and every capacity bound
> are checked by proven code at run time), **zero `sorry`**, over the
> Aeneas-generated model of the Rust that both the solver and the re-check
> run.

Since v0.34.0 (TR-073) there is a third, about the query as the caller
built it:

> The **flattener** `kernel::term_kernel::flatten_tree` is machine-checked
> to be **sound**: the node lists it produces from the caller's trees —
> variables, arrays and functions by name — denote those trees under
> every assignment that agrees with the environment through its own
> variable table, so an accepted certificate refutes the TREES
> (`tree_unsat_sound`, `ext_tree_unsat_sound`) and an accepted model
> satisfies them with every value bound BY NAME (`tree_model_sound`,
> `ext_tree_model_sound`) — **zero `sorry`**, over the Aeneas-generated
> model of the Rust the production path runs.

Everything below qualifies all three sentences. The qualifications are the point.

## The theorem, exactly

In `lean/Sound.lean` (namespace `kernel.spec`):

```lean
theorem lrat_check_sound
    (cnf : Slice (alloc.vec.Vec Std.I32)) (steps : Slice Step)
    (hfit : cnf.val.length + steps.val.length ≤ Std.Usize.max)
    (h : kernel.check_steps cnf steps = ok (core.result.Result.Ok ())) :
    unsat (cnf.val.map (fun c => c.val))
```

with the **standard** semantics (no weakening):

```lean
def unsat (cnf : List (List Std.I32)) : Prop := ∀ σ : Asn, ¬ cnfHolds σ cnf
def cnfHolds (σ) (cnf) : Prop := ∀ c ∈ cnf, clauseHolds σ c        -- conjunction
def clauseHolds (σ) (c)  : Prop := ∃ lit ∈ c, litHolds σ lit       -- disjunction
```

`kernel.check_steps` is the Aeneas translation of
`pub fn check_steps(cnf: &[Vec<i32>], steps: &[Step]) -> Result<(), CoreError>`
(`crates/ordeal-lrat/src/kernel.rs`). `h` is a genuine *accepting run of the
model* (the Rust unit tests exhibit such runs, so the hypothesis is
satisfiable — the theorem is not vacuous). Direction: **soundness only** (accept
⟹ unsat). Completeness (a valid certificate is always accepted) is *not* claimed
and is not needed — a checker is allowed to reject; it must never wrongly accept.

The mathematical core is separate and fully proved:

```lean
theorem pure_check_sound (cnf) (steps) (h : pCheckSteps cnf steps = true) : unsat cnf
```

`pCheckSteps` / `pChecks` / `pCheckRup` are real recursive definitions of the
RUP procedure over plain lists; `kernel_refines_pure` connects the Aeneas model
to them by simulation.

## The trusted computing base (what a wrong result would require)

For `lrat_check_sound` to be *stated* correctly yet *false in reality*, one of
these would have to fail:

1. **The Charon + Aeneas Rust→Lean translation of `kernel.rs` is faithful.**
   This is the largest assumption. `lean/Kernel.lean` is machine-generated
   (`-- THIS FILE WAS AUTOMATICALLY GENERATED BY AENEAS`) from the exact Rust
   source (it carries `Source: 'crates/ordeal-lrat/src/kernel.rs', lines …`
   provenance on every declaration), by pinned Charon/Aeneas revisions
   (`lean/regen.sh`). Aeneas is a research translator and is **not itself
   verified end to end**; we trust it. Mitigations: the checker is small
   (`kernel.rs` is one file), the model is regenerated rather than hand-written,
   and Aeneas models Rust scalar (`i32`/`usize`) semantics including bounds.
2. **Lean's kernel is sound**, and the axioms the proof uses are consistent.
   `#print axioms kernel.spec.lrat_check_sound` reports **only** the three
   standard Mathlib axioms — `propext`, `Classical.choice`, `Quot.sound`.
   **No `sorryAx`, no `native_decide`.** (An earlier version leaned on two
   `native_decide` facts about `i32::MIN`, which pulled the Lean compiler /
   `Lean.ofReduceBool` into the trusted base; those are now proved
   kernel-checked via `simp [core.num.I32.MIN, I32.rMin, I32.max_eq]`, so the
   top-level theorem is as axiom-clean as the mathematical core
   `pure_check_sound`.)
3. **The side condition `hfit` holds.** `|cnf| + |steps| ≤ usize::MAX`. Because
   Lean's `⦃ ⦄` spec is *total* (`spec (fail) = False`), the proof must show the
   run never fails; deletes set store slots to `none` without shrinking, so this
   bound is what keeps the clause store below `usize::MAX` for every push. It is
   physically always true (the slices already reside in a 64-bit address space)
   and does not weaken the guarantee in practice.

## The SAT direction: the witness checker (TR-038 → TR-044 / VER-039)

`lean/SatWitness.lean` (namespace `kernel.spec`, the SAME semantics as above —
`asnOf` is the only new definition) states and proves, `sorry`-free, over the
same Aeneas model of `kernel.rs`:

```lean
/-- DIMACS variable v ≥ 1 reads assignment[v-1]; past the end reads false. -/
def asnOf (assignment : List Bool) : Asn := fun v => assignment.getD (v - 1) false

theorem check_sat_sound
    (cnf : Slice (alloc.vec.Vec Std.I32)) (assignment : Slice Bool)
    (h : kernel.check_sat cnf assignment = ok (core.result.Result.Ok ())) :
    cnfHolds (asnOf assignment.val) (cnf.val.map (fun c => c.val))

theorem check_sat_satisfiable (cnf) (assignment) (h : …) :
    ¬ unsat (cnf.val.map (fun c => c.val))

theorem check_binding_sound
    (assignment : Slice Bool) (bits : Slice Std.I32) (value : Std.U128)
    (h : kernel.check_binding assignment bits value = ok (core.result.Result.Ok ())) :
    ∀ k, (hk : k < bits.val.length) →
      value.val.testBit k = decide (litHolds (asnOf assignment.val) bits.val[k])

theorem verdicts_exclusive
    (cnf : Slice (alloc.vec.Vec Std.I32)) (steps : Slice Step) (assignment : Slice Bool)
    (hfit : cnf.val.length + steps.val.length ≤ Std.Usize.max)
    (hu : kernel.check_steps cnf steps = ok (core.result.Result.Ok ()))
    (hs : kernel.check_sat cnf assignment = ok (core.result.Result.Ok ())) : False
```

Qualifications, in the same spirit as for the UNSAT theorem:

1. **The CNF is the actual argument** (`cnf.val`); the `ordeal-cert/v1`
   bundle, its hash check and its parser stay untrusted. `h` is a genuine
   accepting run of the model (the Rust unit tests exhibit such runs).
2. **`asnOf`'s out-of-range default is never load-bearing.** The strong form
   `check_sat_witnessed` shows every accepted clause has a literal the kernel
   validated (nonzero, non-`i32::MIN`), read from a real slot
   (`1 ≤ |lit| ≤ |assignment|`) and found true. Kernel-review finding recorded
   while proving: `clause_satisfied` stops at the first true literal, so
   literals *after* it in an already-satisfied clause are not validated. That
   cannot affect soundness (a clause with a true literal holds), which is why
   the specification speaks of "a witnessing literal", not "every literal in
   range".
3. **Axiom-clean, and a new gate for how that could silently stop being
   true.** `#print axioms` on all four theorems reports **only** `propext`,
   `Classical.choice`, `Quot.sound` (pinned in `lean/AxiomCheck.lean`). Proving
   them surfaced a regression: `clause_satisfied` computed `|lit|` with
   `i32::unsigned_abs`, which the pinned Aeneas has no model of and emits into
   the generated model as an opaque `axiom core.num.I32.unsigned_abs` — a
   function symbol about which nothing is derivable, so the first proof had to
   state the `check_sat` family conditionally on its contract. TR-038 had
   introduced it and no gate noticed until a pinned theorem reached it. The
   kernel now spells `|lit|` once, through the fully modelled `lit_var` (as
   `check_binding` always did), and the Lean CI job fails on any `^axiom` in a
   generated model (*Generated models carry no axioms*, right after regen).
4. `hfit` in `verdicts_exclusive` is `lrat_check_sound`'s side condition,
   unchanged. Direction: **soundness only**, as above — a rejected witness
   says nothing.

## The query direction: the certificate-carried DAG (#192 phase 4 / TR-062)

Since phase 4 the proven lowering — the blast rules, the term-DAG encoder,
the folding + hashing pass and the Tseitin encoder — lives in the trusted
crate (`crates/ordeal-lrat/src/blast_kernel.rs`, a `#[path]` submodule of
`kernel.rs`, so Charon/Aeneas translate checker and lowering as ONE unit
into `lean/Kernel.lean`: `kernel.*` and `kernel.blast_kernel.*`), and the
solver re-exports it (`ordeal::blast_kernel`): one source, no second copy.
On top of it `kernel::check_query` composes everything into one entry
point an `ordeal-cert/v2` bundle is re-checked with:

```rust
pub fn check_query(ns: &[DagNode], bits: &[bool], roots: &[usize],
                   hints: &[usize], steps: &[Step]) -> Result<Vec<Vec<i32>>, QueryError>
```

It runs `dag_wf` (every node against the widths of the nodes before it),
`roots_wf`, the capacity checks the theorems carry (`encode_fits`,
`tseitin_fits`, the `i32` arena bound, `|cnf| + |steps|`), then
`aig_new` → `encode` → `compact(hints)` → `map_word` → `tseitin` — the
same calls as `solver.rs::lower_with` — and finally `check_steps` on that
CNF. `lean/QueryCheck.lean` (namespace `kernel.spec`) proves, `sorry`-free
and axiom-clean (pinned in `lean/AxiomCheck.lean`):

```lean
theorem dag_wf_spec (ns : Slice kernel.blast_kernel.DagNode) (nbits : Std.Usize) :
    kernel.dag_wf ns nbits ⦃ r =>
      match r with
      | core.result.Result.Ok ws =>
          ws.val.map Std.Usize.val = dagWidths ns.val ∧ DagWF ns.val nbits.val
      | core.result.Result.Err _ =>
          ¬ (DagWF ns.val nbits.val ∧ ∀ w ∈ dagWidths ns.val, w ≤ Std.Usize.max) ⦄

theorem check_query_sound (ns : Slice kernel.blast_kernel.DagNode) (bits : Slice Bool)
    (roots : Slice Std.Usize) (hints : Slice Std.Usize) (steps : Slice kernel.Step)
    (cnf : alloc.vec.Vec (alloc.vec.Vec Std.I32))
    (h : kernel.check_query ns bits roots hints steps = ok (core.result.Result.Ok cnf)) :
    ∀ inp : List Bool, ¬ (∀ (k : Nat) (hk : k < roots.val.length),
      dagBool inp bits.val ns.val (roots.val[k]).val = true)

theorem check_query_refutes_cnf … (h : … = ok (core.result.Result.Ok cnf)) :
    unsat (cnf.val.map (fun c => c.val))
```

`dag_wf_spec` is the **iff** form of the check (total: the run never
fails): `Ok` exactly when the Lean `DagWF` predicate — the side condition
phase 3's `encode_sound` / `dag_refuted` *assumed* — holds and every
width fits `usize` (the only `DagWF` DAGs the Rust check rejects are ones
whose `Concat` / `ZeroExt` / `SignExt` width sum passes `usize::MAX`; it
rejects instead of wrapping). `check_query_sound` is `dag_refuted`'s
conclusion with every hypothesis discharged: `dag_wf_spec` gives `DagWF`,
`roots_wf_spec` the roots condition, `max_width_spec` and
`encode_fits_spec` the gate budget (`1 + n · gateBound W ≤ usize::MAX`),
the run-time tests the `i32` / `usize` capacities, and `dag_refuted` does
the rest. Direction: soundness only, as everywhere in this document —
`TooLarge` and a rejected DAG say nothing.

What a v2 recheck therefore proves: **the lowered term DAG the bundle
carries is unsatisfiable** — under the DAG semantics `dagSim`
(`lean/BlasterDag.lean`, defined directly over Lean `BitVec`: variables
read their bits off the input assignment in node order, constants off the
constant table, every operator by its `BitVec` meaning incl. SMT-LIB's
division by zero; since #192 phase 5 the five formerly derived operators
`BvNot`, `Neg`, `Rotl`, `Sdiv`, `Srem` are node kinds of their own, with
the meanings `~~~`, `-`, `rotateLeft (· % w)`, `smtSDiv`, `srem` and the
proven composite rules of `lean/BlasterDerived.lean`; `gateBound W` is
`70·W² + 70·W + 1` since then). The hints are untrusted by design (`compact_sound`
holds for any hints) and the CNF the bundle also carries for v1 readers
is checked equal to the re-encoding on the untrusted side
(`QueryRecheckError::CnfMismatch`) — not part of the theorem, which does
not depend on the `Ok` payload.

## The SAT direction at the query level: the model re-check (#192 phase 6 / TR-065)

Until phase 6 a `Sat` answer was proven only at the CNF level
(`check_sat_sound` / `check_binding_sound`, above): that the model
satisfies the *query* — the DAG, in the semantics `check_query_sound` is
stated over — went through the untrusted, unproven `eval.rs` evaluator
(`solver.rs::decode_and_check`). `kernel::check_query_model` closes that:

```rust
pub fn check_query_model(ns: &[DagNode], bits: &[bool], roots: &[usize],
                         inp: &[bool]) -> Result<(), ModelError>
```

It runs the same `dag_wf` / `roots_wf` / `max_width` / `encode_fits`
checks as `check_query`, then `dag_nin` (the DAG's primary-input count —
the `Var` widths summed in node order; an `inp` shorter than that is
rejected, never padded), then `aig_new` → `encode` → `simulate` — the
proven encoder and the proven simulator — and requires every asserted
output literal (`eval_lit`) to be true. No new evaluator: `encode_sound`
already says each output literal simulates to its root's `dagBool`
value under every input list. `lean/QueryCheck.lean` proves, `sorry`-free
and axiom-clean (pinned in `lean/AxiomCheck.lean`):

```lean
theorem check_query_model_sound (ns : Slice kernel.blast_kernel.DagNode) (bits : Slice Bool)
    (roots : Slice Std.Usize) (inp : Slice Bool)
    (h : kernel.check_query_model ns bits roots inp = ok (core.result.Result.Ok ())) :
    ∀ (k : Nat) (hk : k < roots.val.length),
      dagBool inp.val bits.val ns.val (roots.val[k]).val = true

theorem query_verdicts_exclusive (ns bits roots hints steps cnf inp)
    (hu : kernel.check_query ns bits roots hints steps = ok (core.result.Result.Ok cnf))
    (hs : kernel.check_query_model ns bits roots inp = ok (core.result.Result.Ok ())) : False
```

`inp.val` is exactly the `inp : List Bool` that `dagBool` reads a `Var`
node's bits from (bit `nin + j` is bit `j`, LSB first, of the `Var`
reached after `nin` earlier input bits), and the conclusion is **the
same `dagBool`** that `check_query_sound` negates — so a SAT and an UNSAT
claim about one query are claims about one semantics, and
`query_verdicts_exclusive` is their one-line contradiction (the
query-level twin of `verdicts_exclusive`). `dag_nin_spec` (`Ok n ⟹ n =
dagNin ns`) and `AigWF_mono` discharge `simulate_spec`'s well-formedness
hypothesis; `check_query_model_loop_spec` carries "the first `k` output
literals are true" through the loop. Direction: soundness only — a
rejected model (`RootFalse`, `ModelTooShort`, a malformed DAG) says
nothing, and the solver degrades such an answer to `Unknown`.

What a v2 SAT recheck therefore proves: **the input bits the bundle
carries satisfy every root of the lowered term DAG it carries**, under
`dagSim`. What it does NOT prove — the remaining trust for `sat`, stated
plainly: that the DAG is the caller's question (the DAG builder,
`dag.rs`), and that the model's named values are the carried input bits
(the builder's `(name, width, Var node)` map, carried in the `inputs`
block; the untrusted `QueryInputs::check_consistent` confirms the
advertised model agrees with the inputs but is not part of the theorem).
The CNF-level witness (`check_sat` / `check_binding`) and the `eval.rs`
self-check still run first in `Solver::check_with_query` as defence in
depth; the answer rests on `check_query_model`. The default `check` /
`check_with_witness` paths are unchanged (CNF witness + evaluator): the
trusted sat gate is where the trusted unsat gate is, `check_with_query`
and `ordeal check --with-query`.

## The term direction: the certificate-carried term (#192 phase 7 / TR-069)

Phases 4–6 prove both verdicts about the **lowered DAG** a bundle
carries — the solver's DAG, after canonicalization (`canon.rs`:
commutative operands reordered, comparisons mirrored, constant-valued
subterms folded) and hash-consing (`dag.rs`). Phase 7 closes that step:
`kernel::check_term_dag` takes the TERM too — the caller's assertions
flattened as they were asked (`dag::flatten`: variables shared by name
and nothing else), in the same `DagNode` spelling, with the untrusted
index map `term node → DAG node` — and verifies, node by node, that the
DAG is a semantics-preserving rewrite of the term:

```rust
pub fn check_term_dag(t: &[DagNode], tbits: &[bool], troots: &[usize], map: &[usize],
                      ns: &[DagNode], bits: &[bool], roots: &[usize]) -> Result<(), TermError>
```

A mapped variable must map to an unused variable of its width (the map
is injective on variables — the one check whose omission would be
unsound, since aliasing two term variables makes the DAG *more*
constrained); a constant to the same constant; an operator to the same
operator over its operands' images, up to a commutative swap or a
comparison mirror, or — when its value does not depend on the inputs:
its cone reads no variable, or only in a branch of an `ite` that a
known constant condition does not select, or only in an operand of a
boolean `and` / `or` that a known constant operand decides — to a
constant of its width and of its value, as the proven `encode` and
`simulate` compute it at the all-false assignment; the roots correspond
one for one. `lean/TermCheck.lean` (namespace `kernel.spec`) proves,
`sorry`-free and axiom-clean (pinned in `lean/AxiomCheck.lean`):

```lean
theorem check_term_dag_sound (t : Slice DagNode) (tbits : Slice Bool) (troots map : Slice Usize)
    (ns : Slice DagNode) (bits : Slice Bool) (roots : Slice Usize)
    (h : kernel.check_term_dag t tbits troots map ns bits roots = ok (core.result.Result.Ok ())) :
    ∀ inp0 inp1 : List Bool, VarsAgree t.val ns.val map.val inp0 inp1 →
      ∀ k (hk : k < troots.val.length),
        dagBool inp0 tbits.val t.val (troots.val[k]).val
          = dagBool inp1 bits.val ns.val (roots.val.getD k 0#usize).val

theorem check_term_unsat_sound … (ht : kernel.check_term_dag … = ok (Ok ()))
    (hq : kernel.check_query ns bits roots hints steps = ok (Ok cnf)) :
    ∀ inp0 : List Bool, ¬ (∀ k (hk : k < troots.val.length),
      dagBool inp0 tbits.val t.val (troots.val[k]).val = true)

theorem check_term_model_sound … (ht : …) (hm : kernel.check_query_model ns bits roots inp1 = ok (Ok ())) :
    ∃ inp0 : List Bool, VarsAgree t.val ns.val map.val inp0 inp1.val ∧
      ∀ k (hk : k < troots.val.length), dagBool inp0 tbits.val t.val (troots.val[k]).val = true

theorem term_verdicts_exclusive … (ht) (hq) (hm) : False

theorem check_input_value_sound (inp : Slice Bool) (offset w : Usize) (value : U128)
    (h : kernel.check_input_value inp offset w value = ok true) :
    ∀ k < w.val, inp.val.getD (offset.val + k) false = value.val.testBit k
```

`VarsAgree t ns map inp0 inp1` says the two input assignments agree on
the variables through the map (a mapped term variable, at its offset
`dagNin` of the prefix before it, reads the same bits as its image at
its own offset); `check_term_unsat_sound` is `check_query_sound` pulled
back through the pushforward of a term assignment,
`check_term_model_sound` is `check_query_model_sound` pushed through the
pullback of a DAG assignment, both over `corr_values` (every mapped term
node has the value of its image — the induction over the term, with
`const_indep`: a constant-valued node's value does not depend on the
inputs). `check_input_value_sound` (7d) is `check_binding_sound`'s twin
at the DAG level and, with `var_offset` (proven to compute `dagNin` of a
prefix), ties an advertised model value to the term variable's input
bits.

What a v3 recheck therefore proves: **the term the bundle carries — the
question as asked, in the `dagSim` semantics — is unsatisfiable, or is
satisfied by the advertised model.** What it does NOT prove, the
remaining trust on the query path, stated plainly: that the term block
is the caller's assertions (`dag::flatten`, a 1:1 serialization with no
semantic decision, which a consumer holding the assertions re-runs and
compares by hash), the variable names, the front ends — and, until
TR-072 (the sliver section below), the sliver.
`canon.rs`, `dag.rs`, `dag::term_map` and `QueryInputs::from_model` are
no longer trusted: a wrong decision in any of them is rejected by the
trusted check, and the solver degrades the verdict to `Unknown`
(`Solver::term_verdict`, `term_sat_verdict`). In v0.31.0 the trusted
term gate was the opt-in `Solver::check_with_term` / `ordeal check
--with-term`; since v0.32.0 it is every entry point's gate (next
section).

## Every answer rests on the term check: the default path (v0.32.0 / TR-070)

Until v0.31.0 the default entry points — `Solver::check`,
`check_with_limit`, `check_with_deadline`, `check_with_witness`, the
sliver one-shots and the CLI's default output — validated the LRAT
proof against the solver's own CNF (`ordeal_lrat::check`) and the model
against the assertions with the untrusted `eval.rs`; the proven query
and term checks ran only when a caller opted in. Since v0.32.0 there is
**one pipeline** (`Solver::solve_core`): lower, search, then the
trusted gate, and every entry point keeps a projection of its result:

- **UNSAT** (`Solver::gate_unsat`): the assertions are flattened as
  asked and mapped onto the lowered DAG (`dag::flatten`,
  `dag::term_map`, untrusted advice); the trusted crate runs
  `check_term_dag` (the DAG is a semantics-preserving rewrite of the
  term, `check_term_dag_sound`) and then `check_query` (the DAG
  re-encoded by the proven lowering, the LRAT proof checked against
  the CNF *it* produced, `check_query_sound`), and the solver's CNF is
  checked equal to the re-encoding. The proof is checked **once**, by
  `check_query`; `ordeal_lrat::check` on the solver's CNF no longer
  runs on this path. `Unsat` ⟹ `check_term_unsat_sound`: no assignment
  to the term's variables makes every asserted root true.
- **SAT** (`Solver::gate_sat`): the model is decoded and re-evaluated
  against the original assertions by `eval.rs` (kept, as defence in
  depth); then the trusted crate runs `check_term_dag`, the CNF-level
  witness check (`check_sat` / `check_binding`), `check_query_model`
  (every root of the DAG true under the model's input bits,
  `check_query_model_sound`) and, for every advertised model value,
  `var_offset` / `check_input_value` through the **term's** own
  variable map (`check_input_value_sound`). `Sat` ⟹
  `check_term_model_sound`: the advertised model satisfies the term.
- Anything the trusted crate rejects degrades to `Unknown` on every
  entry point — never to a wrong answer. The negative control is a
  test-only hook (`solver::tamper`) that corrupts one map entry, or
  swaps two term variables, before the trusted crate sees them, with
  the solver, the search, the proof and the model untouched: `check`
  and its five siblings all return `Unknown`, and decide again when
  the hook is disarmed (`query_term_tests::default_check_rests_on_the_trusted_term_check`,
  `default_sat_rests_on_the_trusted_binding`,
  `sliver_one_shots_rest_on_the_trusted_term_check`). A gate that
  skipped the term check fails those tests (recorded in VE-060).

What this changes for a consumer: nothing in the bytes — the
certificate (CNF + LRAT) and the model `check` returns are the ones
`check_with_term` carries, byte-identical to v0.31.0's over every query
file in the repository; `--with-query` and `--with-term` are unchanged
and cost nothing beyond `check` now. What it changes in the trust base:
`canon.rs`, `dag.rs` (the builder, `term_map`), `eval.rs` and the
model-to-inputs glue leave **every** answer's trust path, not only the
`--with-term` one. **What was still trusted, on every path, in v0.32.0:**
the 1:1 flattening of the assertions into the term (`dag::flatten`, a
post-order walk with no semantic decision — a consumer holding the
assertions re-runs and compares it), the variable names, the SMT-LIB /
Verus front ends — and the sliver lowering (`sliver.rs`, array/UF
elimination into the closed core), until TR-072 put it under the trusted
`check_sliver_lowering` (next section) and TR-073 moved the flattening
and the names into the kernel (`flatten_tree`, the section after it).

## The extended query: the sliver check (TR-072 / `ordeal-cert/v4`)

loom's memory and `pure_call` obligations are not closed-fragment terms:
they are EXTENDED queries (`sliver.rs`: `select`/`store` over
`Array(BV32 → BV8)` with concrete or symbolic indices, uninterpreted
`pure_call`s). `sliver::lower` eliminates them into the closed core —
eager read-over-write into nested `ite`s, Ackermannization of the calls,
pairwise congruence over the reads of one array and the sites of one
function — and everything above proves the LOWERED core. That the core
is the elimination of the extended query was trusted Rust (#247 was a
certified wrong `Unsat` through exactly that step).

Since TR-072 the trusted crate gains
`kernel::sliver_kernel::check_sliver_lowering` (`crates/ordeal-lrat/src/sliver_kernel.rs`,
one translation unit with the rest of the kernel): given the extended
query as asked (`ordeal-ext/v1` — a node list whose constructors are the
closed fragment's plus `Select(aid, idx, s, n)` over a store chain in a
side table and `Call(fid, w, s, n)`; arrays and functions by id, their
names the untrusted side's as variable names are) and untrusted advice —
the map from its nodes to the core's, the read table `(read var, array,
index node)`, the call table `(result var, function, args)` — it checks
node by node that the core is the elimination: a `select` by walking its
chain (two constant indices settle a level statically, equal bits to the
value's image, unequal bits skipped; any other level must be
`ite(index = idx, value, rest)` over the images) down to the read
variable registered for `(array, idx)`; a call to the result variable
registered for its function over its arguments' images; a closed operator
exactly (no rewrite — the sliver makes none); a variable to an
unclassified core variable, the three classes (query variable, read,
call) partitioning the core variables the extended query reaches; the
extended roots' images leading the core roots; and the remaining core
roots being exactly the congruence roots the check itself enumerates
(pairs `p < q` of the read table with one array, skipping two unequal
constants; pairs of the call table with one function and arity). The
roots are computed, not hinted; every table entry must be reached by a
mapped `select` or call (a dead entry is refused).

```lean
abbrev Arrs := Nat → BitVec 32 → BitVec 8            -- an array interpretation
abbrev Ufs  := Nat → List DVal → DVal                 -- a UF interpretation (coerced to the call's width)
-- extSim: dagSim with two more arms — chainRead (the most recent store whose
-- index equals the selected one wins, else the base array) and the call.

theorem check_sliver_lowering_sound … (h : kernel.sliver_kernel.check_sliver_lowering … = ok (Ok ())) :
    (∀ inp0 arrs ufs, ExtSat inp0 ebits arrs ufs eside e eroots →
        ∃ inp1, ∀ k < troots.length, dagBool inp1 tbits t troots[k] = true) ∧
    (∀ inp1, (∀ k < troots.length, dagBool inp1 tbits t troots[k] = true) →
        ∃ inp0 arrs ufs, ExtVarsAgree … ∧ TablesAgree … ∧ ExtSat inp0 ebits arrs ufs eside e eroots)

theorem check_sliver_unsat_sound … (hs : check_sliver_lowering … = ok (Ok ()))
    (ht : kernel.check_term_dag t tbits troots map1 ns bits roots = ok (Ok ()))
    (hq : kernel.check_query ns bits roots hints steps = ok (Ok cnf)) :
    ∀ inp0 (arrs : Arrs) (ufs : Ufs), ¬ ExtSat inp0 ebits arrs ufs eside e eroots

theorem check_sliver_model_sound … (hs) (ht) (hm : kernel.check_query_model ns bits roots inp2 = ok (Ok ())) :
    ∃ inp0 inp1 arrs ufs, VarsAgree t ns map1 inp1 inp2 ∧ ExtVarsAgree … ∧ TablesAgree … ∧ ExtSat …

theorem sliver_verdicts_exclusive … (hs) (ht) (hq) (hm) : False
```

`lean/SliverCheck.lean`: `sliver_corr_values` (under agreement on the
variables and on the tables, every mapped extended node has the value of
its image — the `Core` arm is phase 7's `pMapNode_val`, the `select` arm
the chain-walk lemma, the call arm the table), `pushforward_sat` (an
extended model pushes forward: the extended roots by the correspondence,
every congruence root by functional consistency — Ackermann's theorem is
this lemma) and `pullback_tables_agree` (a core model pulls back: `arrs`
and `ufs` built from the read and call variables' values, well defined
because the congruence roots are complete and a skipped pair is two
constants with unequal bits). The capstones are pinned axiom-clean in
`AxiomCheck.lean`; `TermCheck.lean` and `QueryCheck.lean` are untouched.
What a v4 recheck proves: **the extended query the bundle carries is
unsatisfiable under every array and UF interpretation, or is satisfied
by the interpretation built from the model** (the `ext_model` block:
arrays at every read's index value, functions at every call's argument
values). What stayed trusted in v0.33.0: the 1:1 flattening of the
`ExtBoolTerm`s into the `ext` block (`sliver::flatten_ext`, one walk with
the lowering, no semantic decision — a consumer re-runs it and compares
by hash), the variable, array and function names, and the front ends —
the flattening and the names moved into the kernel with TR-073 (next
section). Every sliver
entry point (`Solver::from_sliver` and every `check*` on it, the
one-shots, `prove_equiv_sliver`) runs the check before the term and
query checks; a rejection is `Unknown`. A solver that lowers through
`sliver::lower` itself and asserts the core is a core solver: it gets the
term and query checks about the core, not the sliver check.

## The tree direction: the proven flattener (TR-073 / v0.34.0)

Phase 7 and TR-072 are stated over NODE LISTS — the `term` block and the
`ext` block a bundle carries. The step from the caller's TREES
(`BoolTerm` / `ExtBoolTerm`: variables, arrays and functions by NAME) to
those lists was untrusted Rust (`dag::flatten`, `sliver::flatten_ext`),
and so were the names and the one untrusted guard that made the
flattening's name identification sound (a name at two widths,
`check_var_widths_bool` — finding F2 of
`docs/design/flattener-proof.md`). TR-073 moves the flattening into the
trusted crate, over the kernel's own tree type:

```rust
pub enum TBv { Const(u128, usize), Var(Vec<u8>, usize), Add(Box<TBv>, Box<TBv>), …,
               Select(Box<TArray>, Box<TBv>), Call(Vec<u8>, usize, Box<TArgs>) }
pub enum TArray { Var(Vec<u8>), Store(Box<TArray>, Box<TBv>, Box<TBv>) }
pub enum TArgs { Nil, Cons(Box<TBv>, Box<TArgs>) }
pub enum TBool { Eq(Box<TBv>, Box<TBv>), …, Not(Box<TBool>), And(..), Or(..) }
pub fn flatten_tree(ts: &[TBool]) -> Result<Flat, FlatError>
pub fn project_core(nodes: &[ExtNode]) -> Result<Vec<DagNode>, FlatError>
pub fn check_tree_model(var_node, var_width, map, ns, inp, values) -> bool
pub fn check_tree_model_ext(var_node, var_width, emap, t, map, ns, inp, values) -> bool
```

`flatten_tree` (`crates/ordeal-lrat/src/term_kernel.rs`, a `#[path]`
submodule of `kernel.rs`: one Aeneas translation unit with the checker,
the lowering and the sliver check) is the post-order, left-to-right walk
`dag::flatten` and `sliver::flatten_ext` performed: variables shared BY
NAME, one node per name and a second width for a name REFUSED
(`FlatError::NameWidth` — F2 is now a kernel error, not a guard),
constants interned by value and width, arrays and functions numbered by
first appearance, every operator its own node. Its output is the `ext`
block (`nodes`, `bits`, `side`, `roots`) plus the variable table (name,
width, node); `project_core` is the `term` block of a closed tree.
`check_tree_model` / `check_tree_model_ext` bind a model BY NAME through
that table: entry `k`'s node, through the map(s), reads the value
advertised under entry `k`'s name (`var_offset` / `check_input_value`,
the phase-7 binding; the extended one also checks the term node is a
`Var` of the entry's width).

`lean/TreeFlatten.lean` (namespace `kernel.spec`) gives the tree a
semantics — `treeBv` / `treeBool`: `dagNodeVal`'s arms over the
children's values, an environment `TEnv := Name → (w : Nat) → BitVec w`,
array and UF interpretations keyed by name (`NArrs`, `NUfs`) — and
proves, `sorry`-free and axiom-clean (pinned in `AxiomCheck.lean`):

```lean
theorem flatten_tree_sound (ts : Slice TBool) (f : Flat)
    (h : flatten_tree ts = ok (Ok f)) :
    Inv f ∧ f.roots.val.length = ts.val.length ∧
    ∀ env arrs ufs inp, VarAgree f env inp → ∀ k (hk : k < ts.val.length),
      extBool inp f.bits.val (arrsI f arrs) (ufsI f ufs) f.side.val f.nodes.val (rootOf f k)
        = treeBool env arrs ufs ts.val[k]

theorem tree_unsat_sound … (hf : flatten_tree ts = ok (Ok f)) (he : e.val = f.nodes.val)
    (hp : project_core e = ok (Ok t)) (htS : tS.val = t.val) (htb : tbits.val = f.bits.val)
    (htr : troots.val = f.roots.val)
    (ht : check_term_dag tS tbits troots map ns bits roots = ok (Ok ()))
    (hq : check_query ns bits roots hints steps = ok (Ok cnf)) :
    ∀ (env : TEnv) (arrs : NArrs) (ufs : NUfs), ¬ TreeSat env arrs ufs ts.val

theorem tree_model_sound … (hm : check_query_model ns bits roots inp2 = ok (Ok ()))
    (hvn : vn.val = f.var_node.val) (hvw : vw.val = f.var_width.val)
    (hb : check_tree_model vn vw map ns inp2 values = ok true) :
    ∃ env : TEnv, (∀ arrs ufs, TreeSat env arrs ufs ts.val) ∧
      ∀ k < nvars f, img map.val (varNodeOf f k) ≠ NONE →
        env (varName f k) (varWidthOf f k)
          = BitVec.ofNat (varWidthOf f k) (values.val.getD k 0#u128).val

theorem tree_verdicts_exclusive … : False
theorem ext_tree_unsat_sound … (hs : check_sliver_lowering e ebits eside eroots map … = ok (Ok ()))
    (ht : …) (hq : …) : ∀ (env : TEnv) (arrs : NArrs) (ufs : NUfs), ¬ TreeSat env arrs ufs ts.val
theorem ext_tree_model_sound … (hb : check_tree_model_ext vn vw map t map1 ns inp2 values = ok true) :
    ∃ env narrs' nufs' arrs ufs inp1, TreeSat env narrs' nufs' ts.val ∧
      TablesAgree t.val tbits.val reads.val calls.val cargs.val arrs ufs inp1 ∧
      (∀ a < narrs f, narrs' (arrName f a) = arrs a) ∧ (∀ g < nfuncs f, nufs' (funName f g) = ufs g) ∧
      ∀ k < nvars f, img map.val (varNodeOf f k) ≠ NONE → img map1.val (…).val ≠ NONE →
        env (varName f k) (varWidthOf f k) = BitVec.ofNat (varWidthOf f k) (values.val.getD k 0#u128).val
theorem ext_tree_verdicts_exclusive … : False
```

The proof is a structural induction over the tree with the generated
(`partial_fixpoint`) definitions unfolded: a structural invariant of the
flattening state (`Inv`: the tables consistent, every table variable a
`Var` of its width, names injective — one node per name, one name per
node — every constant memo entry a `Const` over its own bits, every
select and call naming a registered array / function) and a semantic
conclusion per subtree stated for EVERY later state (`TreeCorr`: the
node denotes the tree under every assignment that agrees with the
environment through the table, `VarAgree`). The two transports are
`layout_exists` (an environment lays out into inputs) and `envOf_agree`
(inputs read back into an environment, well defined because the
kernel's own lookup made the names injective) — this is where F2's
guard used to sit; the kernel refuses the shape itself, so the proof
needs no guard. The by-name interpretations of the extended capstone
are read through the tables from the id-keyed ones TR-072 binds to the
model's reads and calls (`narrsOf`, `nufsOf`).

What this changes on the untrusted side: `ordeal::mirror` copies a
`BoolTerm` / `ExtBoolTerm` into the kernel's tree constructor for
constructor (names as bytes, no interning, no ordering — a bijection,
tested: `to_bool(of_bool(t)) == t` over every seeded corpus);
`QueryTerm::flatten` and `flatten_sliver` call `flatten_tree`
(`project_core` on the core path) and take the variable table from the
kernel; the model-binding re-checks run `check_tree_model` /
`check_tree_model_ext`; `dag::flatten` stays as the differential twin
(`flatten_tree ∘ of_bools == dag::flatten` over the latency, bmc,
`0x192`, `0xC0FFEE` and sliver corpora — the positive control that let
the production path switch with no bundle change: every term and ext
block is byte-identical). The untrusted width guard stays as defence in
depth; `a_name_at_two_widths_is_refused_by_the_kernel_itself` disarms
it and shows every entry point `Unknown` on F2's shape. Along the way
the lowering's raw-constant comparison (#262, F1: `x = 0x1FF:8` left
`Unknown`; two reads at indices equal in bits were two reads with no
congruence root) is fixed by masking at the lowering
(`sliver::masked_bv`, `as_const`, memo keys) — the kernel and the DAG
builder are unchanged and raw, so the blocks stay byte-identical.

**What stays trusted after TR-073, on every path:** the 1:1 copy of the
trees into the kernel's mirror type (`mirror.rs`, one `match` arm per
constructor), and the SMT-LIB / Verus front ends. The flattening, the
variable / array / function names and the width guard are no longer in
the list: an answer rests on the query AS THE CALLER BUILT IT.

## Out of scope (explicitly NOT proven)

- **Certificate text parsing.** The public entry point
  `ordeal_lrat::check(cnf, certificate: &str)` runs an **unverified**
  `parse_certificate` (in `lib.rs`) and *then* calls the proven
  `check_steps`. Important: `check_steps` re-validates the parsed steps against
  the CNF independently, so a parser bug can only cause a **false rejection**,
  never a false "unsat". Soundness of `check()` therefore reduces to soundness
  of `check_steps` plus the CNF being the one you intended.
- **DIMACS parsing** (the `cnf: &[Vec<i32>]` is passed in already parsed).
- **I/O, the WebAssembly component boundary, and the host embedding.**
- **The SAT search.** The CDCL engine that *emits* certificates is untrusted
  by design. A bug there can only produce a certificate the checker rejects.
- **The query-to-CNF translation, above the term DAG.** An encoding bug
  gives a **certified wrong answer**, because the checker certifies the
  CNF it is given (#182). Since #192 phase 3 the lowering from the term
  DAG to the CNF *is* proven, end to end, over the Aeneas model of
  `blast_kernel.rs` — the code the solver runs (`solver.rs::lower_with`):
  `encode` builds the AIG from a `DagNode` list by calling the proven rule
  for every node (`encode_sound`, `lean/BlasterDag.lean`, against a DAG
  semantics defined directly over Lean `BitVec`); `compact` applies the
  constant folding and structural hashing (`compact_sound`,
  `lean/BlasterCompact.lean`, for any hints — the hints only steer
  sharing and are checked); `tseitin` emits the CNF
  (`tseitin_sat_preserving`, `lean/BlasterTseitin.lean`); and
  `dag_refuted` (`lean/BlasterCapstone.lean`) composes the three with
  `lrat_check_sound`:

  ```lean
  theorem dag_refuted (ns : Slice DagNode) (bits : Slice Bool) (roots : Slice Std.Usize) (W : Nat)
      (hdag : DagWF ns.val bits.val.length) (hW : ∀ w ∈ dagWidths ns.val, w ≤ W)
      (hcap : 1 + ns.val.length * gateBound W ≤ Usize.max)
      (hroots : ∀ r ∈ roots.val, r.val < ns.val.length ∧ (dagWidths ns.val).getD r.val 0 = 1)
      (aig0 : Aig) (hnew : aig_new = ok aig0)
      (words : alloc.vec.Vec (alloc.vec.Vec Lit)) (outs : alloc.vec.Vec Lit) (aig1 : Aig)
      (henc : encode aig0 ns bits roots = ok ((words, outs), aig1))
      (hints : Slice Std.Usize) (aig2 : Aig) (map : alloc.vec.Vec Lit)
      (hcomp : compact aig1 hints = ok (aig2, map))
      (outs2 : alloc.vec.Vec Lit)
      (hmap : map_word (alloc.vec.Vec.deref map) (alloc.vec.Vec.deref outs) = ok outs2)
      (hi32 : (aig2.nodes.val.length : Int) ≤ I32.max)
      (hcapT : 1 + 3 * aig2.nodes.val.length + outs2.val.length < Usize.max)
      (cnf : alloc.vec.Vec (alloc.vec.Vec Std.I32))
      (htse : tseitin aig2 (alloc.vec.Vec.deref outs2) = ok cnf)
      (steps : Slice kernel.Step)
      (hfit : cnf.val.length + steps.val.length ≤ Std.Usize.max)
      (hchk : kernel.check_steps ⟨cnf.val, cnf.property⟩ steps = ok (core.result.Result.Ok ())) :
      ∀ inp : List Bool, ¬ (∀ (k : Nat) (hk : k < roots.val.length),
        dagBool inp bits.val ns.val (roots.val[k]).val = true)
  ```

  `dagBool inp bits ns r` is the boolean value of root `r` under the DAG
  semantics `dagSim` (variables read their bits off `inp` in node order,
  constants off the table `bits`); the conclusion is "no input assignment
  makes every asserted root true", i.e. the DAG is unsatisfiable. The
  side conditions are the DAG's well-formedness (`DagWF`: operands are
  earlier nodes of agreeing, positive widths — what the sort checker
  guarantees and the DAG builder produces by construction), a width bound
  `W` for the gate budget, and the `usize`/`i32` capacities every kernel
  function carries. All four new capstones (`encode_sound`,
  `compact_sound`, `dag_refuted`, `dag_refuted_raw`) are pinned
  axiom-clean in `lean/AxiomCheck.lean`.

  Since phase 4 the `DagWF` side condition is no longer assumed: it is
  decided by the proven `kernel::dag_wf` (`dag_wf_spec`, above), and
  `check_query_sound` has no hypotheses. What is *still not* proven, and
  therefore trusted when a verdict is read **as a statement about the
  assertions a caller made** rather than about the DAG a v2 bundle
  carries, was (through v0.31.0 on the default path): the DAG builder
  (`dag.rs`: which `DagNode` is made for which term, variable sharing by
  name, hash-consing) — a wrong decision there changes the question
  asked, as the old term walk could; canon (`canon.rs`, including
  constant folding via `eval.rs`); the sliver (`sliver.rs`); the SMT-LIB
  and Verus front ends; and for a **`sat`** verdict the builder's
  variable map, that the `Var` node the model value is written into is
  the one made for that name. The derived ops (`bvnot`, `bvneg`,
  `bvrotl`, `bvsdiv`, `bvsrem`) are `DagNode` constructs with **proven**
  composite rules since #192 phase 5 / TR-064 (`lean/BlasterDerived.lean`'s
  `blast_bvnot_bitvec`, `blast_neg_bitvec`, `blast_rotl_bitvec`,
  `blast_sdiv_bitvec`, `blast_srem_bitvec` against `~~~A`, `-A`,
  `A.rotateLeft (B.toNat % w)`, `A.smtSDiv B`, `A.srem B`), lowered as
  nodes on every path since v0.28.0, so no rewrite of them is trusted.
  **Since #192 phase 7 / TR-069** the trusted `check_term_dag` relates
  the term to the DAG and the proven `var_offset` / `check_input_value`
  bind the model values through the term's own variable map — on the
  `check_with_term` / `--with-term` path in v0.31.0, and **on every path
  since v0.32.0 / TR-070** (the section above), so the DAG builder,
  canonicalization and `eval.rs` have left this list, and **since
  TR-072** the sliver lowering has too (`check_sliver_lowering`, the
  section above), and **since TR-073** the flattening of the trees into
  the term / `ext` block and the variable, array and function names
  (`flatten_tree`, `check_tree_model`, the section above). What stays:
  the 1:1 copy of the trees into the kernel's mirror type (`mirror.rs`,
  constructor for constructor, bijection-tested) and the front ends.
  `dag::strash_hints` is untrusted by design: it only reproduces the
  sharing decisions of the old `Aig::and` strash so the shipped CNF stays
  byte-identical, and `compact_sound` holds for any hints. The shipped
  `cnf.rs` and `aig.rs` are no longer on the production path (they serve
  the per-family differentials and the gate-identity tests). Evidence for
  the unproven pieces is tests and the Z3 differential; closing them is
  #192 phase 5, planned in `docs/design/query-cnf-gap.md`. The Kani
  harnesses (`blast/proofs.rs`, bounded at widths 8/32/64) target the same
  `blast_kernel` rules on the reference arena, so they are a second,
  independent witness of the rule theorems — not of the encoder, the
  compaction pass or `check_query` (see `proofs.rs`).

## Model freshness: generated, not checked (TR-034)

The model the proofs reason about — `lean/Kernel.lean`, since #192 phase 4
ONE file holding the checker (`kernel.*`) and the proven lowering
(`kernel.blast_kernel.*`, from `crates/ordeal-lrat/src/blast_kernel.rs`,
a `#[path]` submodule of `kernel.rs`) — is a **build product, not a
committed artifact**. `lean/regen.sh` produces it from the Rust sources
with Charon/Aeneas pinned in exactly one place (`lean/toolchain-pins.env`),
and the *Lean model + soundness proof* CI job regenerates it **before every
proof build**. A proof about a stale model is therefore unrepresentable:
there is no committed model that could go stale, and a `kernel.rs` /
`blast_kernel.rs` change whose translation breaks a proof fails that
required job directly. (History: freshness was originally enforced by a
separate drift-diff workflow — issue #44 — which this construction absorbed
and retired; see `docs/design/checker-single-sourcing.md`.)

**Width scope of the blaster proofs.** Every blaster theorem holds at
every width `w >= 1`, the shift and rotate theorems included. Until #201
the four of them (`blast_shl_bitvec`, `blast_lshr_bitvec`,
`blast_ashr_bitvec`, `blast_rotr_bitvec`) assumed a power-of-two width
(`hpow : 2 ^ stages = w`), and the reference copy's `rotr` was wrong at
other widths for amounts `>= w`. Now the reference copy mirrors the real
blaster (#182/#183) exactly: `stage_count` is `ceil(log2 w)` (proved exact
in `stage_count_spec`: `2^(stages-1) < w <= 2^stages`), the out-of-range
test covers the amount bits above the stages, and `rotr` reduces the
amount mod `w` with `blast_urem` at non-power-of-two widths. The three
shift theorems (`lean/BlasterShift.lean`) and the rotate theorem
(`lean/BlasterRotr.lean`, after the divider proofs it composes with) take
only `0 < w` and a capacity bound; there is no width hypothesis left. The
reference-to-real differential test (VER-051) compares every mirrored op,
`rotr` on its full amount domain, exhaustively at widths 1 to 8, sampled
at 9 to 16, and sampled at wider widths up to 128; it also pins the
mirror's `stage_count` against the real formula and `is_power_of_two` at
every width up to 4096 and at the `usize` extremes.

What this does **not** discharge: Charon/Aeneas translation faithfulness at
the pinned revisions. That residual is the target of the adversarial
dual-mechanisation work (issue #47 / TR-035).
